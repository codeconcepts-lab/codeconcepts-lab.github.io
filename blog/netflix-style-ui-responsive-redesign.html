What We're Building

A Production-Quality Streaming UI Without a Single npm Install

The Netflix UI is one of the most recognisable interaction patterns on the web — horizontal carousels, hover-expand cards, smooth scroll navigation, and row-based content organisation. Millions of developers have tried to replicate it. Most reach for a carousel library. This post argues you shouldn't, and shows you exactly why not.

What you'll build by the end of this tutorial is a fully interactive multi-row content carousel that implements the core Netflix interaction model: keyboard-accessible scroll navigation, CSS-driven card hover expansion, smooth scrollbar-hidden track scrolling, and a data-driven architecture that separates content from rendering logic. The entire implementation fits comfortably in under 12KB.

  • Multi-row carousel layout with labelled content sections
  • Smooth horizontal scroll with prev/next navigation buttons
  • CSS-only card hover expansion with title reveal
  • A data model that cleanly separates content from UI logic
  • Touch-friendly scrolling that works on mobile without extra code
  • Full keyboard accessibility — Tab, Enter, and arrow key navigation
The Brief

Why Not Just Use a Carousel Library?

The first instinct when building a horizontal scroll carousel is to search npm. Swiper.js, Slick, Glide — there are dozens of options, each with hundreds of kilobytes of JavaScript and CSS, configuration APIs that take hours to understand, and opinionated markup structures that fight your layout as often as they help it.

The Cost of Dependencies

Every library dependency is a contract. It comes with a bundle size cost (Swiper.js alone ships at 140KB+ minified), a maintenance cost (version upgrades, API changes, security patches), a debugging cost (when behaviour diverges from what you expect, the abstraction layer makes the root cause harder to find), and a performance cost (libraries optimise for general cases, not yours specifically). For a UI pattern as straightforward as a horizontal card scroll, the dependency cost is almost never justified.

What CSS Can Do That JavaScript Shouldn't

The most important architectural decision in a Netflix-style carousel is understanding which behaviour belongs to CSS and which to JavaScript. CSS handles: the horizontal scroll container, the card aspect ratio, the hover expansion transition, the title reveal animation, and the fade gradients on the scroll edges. JavaScript handles: the navigation button click events, programmatic scrolling, and the data rendering loop. When you let CSS do what it's designed for, the JavaScript stays lean and purposeful.

The Architecture Decision

The carousel in this tutorial uses a data-driven rendering approach: content lives in a JavaScript data structure, and a single rendering function loops over it to produce the DOM. This makes the UI trivially easy to update (change the data, re-render), and keeps all the imperative logic in one place. The CSS system uses custom properties for theming, which means each row can have a distinct accent colour by setting a single variable on its container element.

"Every carousel library you install is solving a problem you could solve in 40 lines of CSS and 30 lines of JavaScript. The library exists for developers who haven't yet taken the time to understand what the browser already gives them for free."

Step 01 · HTML Structure

Semantic Markup That Lets CSS Do the Heavy Lifting

The HTML for a Netflix-style carousel is simpler than you'd expect. The entire layout is built on three nested elements: a section wrapper for each content row, a scrollable track container, and individual card elements. The key structural decisions — which elements get which roles — are what make the CSS system work cleanly.

Row Architecture

Each content row is a <section> with a labelled heading and a scroll track. The track is a single <div> with overflow-x: auto and scrollbar-width: none applied — this gives us native scroll behaviour (including touch momentum scrolling on iOS) while hiding the browser's scrollbar. The cards are direct children of the track, sized with flex: 0 0 auto to prevent them from shrinking.

<section class="carousel-row" data-accent="#BB86FC">
  <h2 class="row-title">Trending Now</h2>
  <div class="row-track-wrap">
    <button class="nav-btn nav-btn--prev" aria-label="Scroll left">
      <svg>...</svg>
    </button>
    <div class="row-track" role="list">
      <article class="content-card" role="listitem" tabindex="0">
        <div class="card-thumbnail">
          <img src="..." alt="Show Title" loading="lazy">
        </div>
        <div class="card-overlay">
          <h3 class="card-title">Show Title</h3>
          <div class="card-meta">2024 · Drama · 8 Episodes</div>
        </div>
      </article>
      <!-- More cards... -->
    </div>
    <button class="nav-btn nav-btn--next" aria-label="Scroll right">
      <svg>...</svg>
    </button>
  </div>
</section>

Accessibility Decisions

The track uses role="list" and each card uses role="listitem" — this restores list semantics that are stripped by list-style: none in some screen readers. Cards are tabindex="0" so they're keyboard focusable. Navigation buttons carry aria-label attributes with directional context. The result is a carousel that works correctly with a screen reader without any ARIA acrobatics.

Step 02 · CSS Architecture

The Scroll Container, Hover System, and Custom Property Theming

The CSS does three distinct jobs: it creates the scrollable track layout, it handles all the card hover animation (including the expand-on-hover effect Netflix is famous for), and it implements per-row accent colour theming via custom properties. None of these require JavaScript.

The Scroll Track

.row-track-wrap {
  position: relative;
  /* Clip the nav buttons at the track edges */
}

.row-track {
  display: flex;
  gap: 0.5rem;
  overflow-x: auto;
  scroll-behavior: smooth;
  /* Native touch momentum scroll on iOS */
  -webkit-overflow-scrolling: touch;
  /* Hide scrollbar: Firefox */
  scrollbar-width: none;
  /* Padding so scaled cards don't clip at edges */
  padding: 0.5rem;
}

/* Hide scrollbar: Chrome/Safari/Edge */
.row-track::-webkit-scrollbar {
  display: none;
}

Card Hover Expansion

The hover expansion is pure CSS — no JavaScript involved. The card scales up on :hover and :focus-visible, and the overlay fades in simultaneously using a CSS transition. The key insight is using transform: scale() rather than changing width/height — scale doesn't trigger layout reflow, which keeps the animation at 60fps.

.content-card {
  flex: 0 0 180px;
  aspect-ratio: 16 / 9;
  border-radius: 4px;
  position: relative;
  overflow: visible; /* Allow scale to exceed bounds */
  cursor: pointer;
  transition: transform 0.25s cubic-bezier(0.4, 0, 0.2, 1),
              box-shadow 0.25s ease;
  /* Prevent z-index stacking issues */
  isolation: isolate;
}

.content-card:hover,
.content-card:focus-visible {
  transform: scale(1.15);
  box-shadow: 0 16px 40px rgba(0, 0, 0, 0.7);
  z-index: 10;
}

/* Overlay reveals on hover */
.card-overlay {
  position: absolute;
  inset: 0;
  background: linear-gradient(
    to top,
    rgba(0, 0, 0, 0.9) 0%,
    rgba(0, 0, 0, 0.3) 50%,
    transparent 100%
  );
  opacity: 0;
  transition: opacity 0.2s ease;
  padding: 0.75rem;
  display: flex;
  flex-direction: column;
  justify-content: flex-end;
}

.content-card:hover .card-overlay,
.content-card:focus-visible .card-overlay {
  opacity: 1;
}

Per-Row Theming with Custom Properties

Each row sets a data-accent attribute. A small JavaScript pass reads this attribute and writes it as a CSS custom property on the row element. This means accent colour is defined in the data, applied via CSS, and requires zero per-row style rules.

/* Set on .carousel-row via JS: style.setProperty('--row-accent', accentColor) */
.row-title::after {
  content: '';
  display: block;
  width: 3rem;
  height: 2px;
  background: var(--row-accent, #BB86FC);
  margin-top: 0.5rem;
}

.nav-btn:hover {
  background: var(--row-accent, #BB86FC);
}
Step 03 · JavaScript Engine

Data-Driven Rendering and the Navigation System

The JavaScript in this build has two responsibilities: rendering the DOM from a data source, and handling scroll navigation. That's it. Everything visual is CSS. Keeping the JavaScript boundary this tight means the entire script stays under 3KB and remains trivially easy to extend.

The Data Model

const catalogData = [
  {
    id: 'trending',
    title: 'Trending Now',
    accent: '#BB86FC',
    items: [
      { id: 1, title: 'Midnight Refactor', year: 2024, genre: 'Thriller' },
      { id: 2, title: 'The CSS Awakens', year: 2024, genre: 'Sci-Fi' },
      { id: 3, title: 'Array of Darkness', year: 2023, genre: 'Horror' },
      // ...more items
    ]
  },
  {
    id: 'new-releases',
    title: 'New Releases',
    accent: '#03DAC6',
    items: [ /* ... */ ]
  }
];

The Renderer

A single renderCatalog() function loops over the data and builds the DOM using insertAdjacentHTML — faster than repeated appendChild calls because it minimises reflow triggers. Template literals make the HTML clean and readable while keeping it in the JavaScript layer where the data lives.

function renderCard(item) {
  return `
    <article class="content-card" role="listitem" tabindex="0"
      data-id="${item.id}" aria-label="${item.title}">
      <div class="card-thumbnail"
        style="background: hsl(${item.id * 47}, 40%, 20%)">
      </div>
      <div class="card-overlay">
        <h3 class="card-title">${item.title}</h3>
        <div class="card-meta">${item.year} · ${item.genre}</div>
      </div>
    </article>
  `;
}

function renderRow(row) {
  const cards = row.items.map(renderCard).join('');
  return `
    <section class="carousel-row" id="${row.id}"
      style="--row-accent: ${row.accent}">
      <h2 class="row-title">${row.title}</h2>
      <div class="row-track-wrap">
        <button class="nav-btn nav-btn--prev"
          aria-label="Scroll ${row.title} left">‹</button>
        <div class="row-track" role="list">${cards}</div>
        <button class="nav-btn nav-btn--next"
          aria-label="Scroll ${row.title} right">›</button>
      </div>
    </section>
  `;
}

function renderCatalog(container, data) {
  container.insertAdjacentHTML('beforeend', data.map(renderRow).join(''));
  initNavigation(container);
}

Navigation System

Navigation buttons use event delegation — one listener on the container, not one per button. When a button is clicked, the handler walks up to its parent track-wrap, finds the track sibling, and calls scrollBy(). The scroll amount is dynamically calculated from the track's visible width, so navigation distance scales correctly at every breakpoint.

function initNavigation(container) {
  container.addEventListener('click', (e) => {
    const btn = e.target.closest('.nav-btn');
    if (!btn) return;

    const wrap = btn.closest('.row-track-wrap');
    const track = wrap.querySelector('.row-track');
    // Scroll by one full visible width
    const delta = track.offsetWidth * 0.85;
    const direction = btn.classList.contains('nav-btn--prev') ? -1 : 1;

    track.scrollBy({ left: delta * direction, behavior: 'smooth' });
  });
}
Key Engineering Patterns

Six Patterns That Make This Build Worth Studying

CSS-First Animation

Every visual transition — card hover expansion, overlay fade-in, button highlight — is handled by CSS transitions, not JavaScript. This offloads animation work from the main thread to the compositor thread, ensuring animations stay at 60fps regardless of JavaScript execution cost. The rule: if CSS can do it, CSS does it.

Native Scroll Over Custom Scroll

Using overflow-x: auto with scroll-behavior: smooth and -webkit-overflow-scrolling: touch gives you native scroll — momentum scrolling on iOS, trackpad physics on macOS, touch swipe on Android — without a single line of touch event handling code. Libraries solve this with thousands of lines; the browser solves it for free.

Event Delegation

Rather than attaching click handlers to each navigation button individually, a single event listener on the container catches all button events via e.target.closest(). This pattern scales: add 100 more rows and the event listener count stays at one. It also means dynamically added rows work automatically without re-binding.

Custom Property Theming

Per-row accent colours are set as CSS custom properties on the row element, applied from the data model at render time. This makes theming declarative — the data says what the colour is, CSS applies it everywhere it's needed. Adding a new coloured element to a row requires zero new JavaScript.

Template Literal Rendering

HTML generation via template literals keeps markup and the data that populates it in the same place, making the relationship between data shape and DOM structure immediately obvious. It avoids the verbosity of DOM API methods (createElement, setAttribute) while remaining faster than framework virtual DOM diffing for this use case.

Dynamic Scroll Calculation

The scroll step is calculated at click time from the track's current offsetWidth rather than hardcoded. This means the same scroll button works correctly at 320px mobile width and 1440px desktop width without any breakpoint-specific logic. The layout determines the scroll amount — never a magic number.

What You've Built

A Production-Pattern UI With Nothing You Don't Need

Zero-Dependency Architecture

The complete implementation — HTML structure, CSS layout and animation system, JavaScript rendering and navigation — ships in under 12KB with no npm, no bundler, no build step, and no version lock-in. The only dependency is the browser, which you already have.

Native Touch & Scroll Support

Touch swipe, momentum scrolling on iOS, trackpad physics on macOS, and mouse wheel scrolling all work without a single line of touch event handling code. Native scroll APIs provide all of this for free when you let the browser do its job.

60fps Animation at All Times

Every animation uses CSS transform and opacity — properties that the browser can composite on the GPU without triggering layout or paint. The main JavaScript thread never touches the animation pipeline, so there's no jank regardless of JS execution cost.

Fully Accessible by Default

Semantic HTML roles, explicit ARIA labels on navigation controls, focus-visible states for keyboard users, and screen reader-compatible list structure — accessibility is built in from the start, not bolted on after the fact.

Data-Driven and Extensible

Adding a new content row requires only a new entry in the data array. The renderer handles everything else. The same pattern scales to hundreds of rows and thousands of items — and because rendering is separated from data, swapping in a real API later requires changing only one function.

Patterns That Transfer Everywhere

Event delegation, CSS-first animation, custom property theming, and data-driven rendering are not carousel-specific patterns. They are general-purpose frontend engineering principles that apply to every UI component you'll build from here — this is the point of Day 01.
