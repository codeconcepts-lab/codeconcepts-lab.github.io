01 Project Overview

A Platform Built for the Complexity of Real-World Logistics

Nigeria's on-demand economy is among Africa's fastest-growing — but it's also among its most operationally complex. Nexora engineered a coordinated ecosystem to compete with industry giants.

Consumers expect Uber-speed delivery. Riders need seamless dispatch. Vendors require inventory and order management. Employers need to coordinate task-based workforces. No single off-the-shelf solution handles all of this simultaneously, and fragmented tools create friction at every handoff.

Nexora was engaged to design and architect Scooty XP from the ground up — not as a single app, but as a coordinated ecosystem of five role-specific applications that share a unified backend, a consistent design language, and a real-time operational layer.

  • Architect five distinct apps that behave as one cohesive platform
  • Design role-specific UX flows without sacrificing cross-app consistency
  • Engineer real-time dispatch and order state synchronisation
  • Build a marketplace infrastructure ready to scale

02 The Challenge

Zero Tolerance for Operational Chaos

"The defining question wasn't 'how do we build five apps?' — it was 'how do we build one platform that happens to have five entry points?' That framing changed every architecture decision we made."

Role Fragmentation Without Coherence

Each user role has entirely different success metrics and interaction patterns. A customer wants speed. A rider needs frictionless navigation. A vendor needs to manage orders without leaving their counter. Designing experiences that feel purposeful required a unified design system enforced across every app from day one.

Real-Time State Across Distributed Sessions

When an order is placed, three other apps must respond simultaneously — rider dispatch, vendor notification, and logic evaluation in under two seconds. Engineering this level of synchronisation on infrastructure suited to Nigeria's variable connectivity was the platform's defining technical constraint.

03 Process & Discovery

Ecosystem-First Thinking.

01

Ecosystem Mapping & Operational Logic

Full order lifecycle and cross-role workflow analysis. Defined every state change, every notification trigger, and every data dependency before design began.

02

Shared Design System & Component Library

Built a unified UI component set covering all five apps — ensuring visual and interaction consistency while enabling role-specific customisation within defined constraints.

03

Role-Specific UX Architecture

Designed each app's information hierarchy around its user's primary job-to-be-done — rider app for one-handed use, shop app for counter-speed fulfilment.

04

Cross-Platform Development & Real-Time

React Native across iOS and Android for all five apps, connected to a Node.js + Firebase backend. Real-time dispatch logic and geolocation integrated throughout.

05

Store Submission, QA & Launch

Coordinated App Store and Google Play submission across all five apps simultaneously, with cross-role QA testing covering the complete order-to-delivery lifecycle.

04 Visual & UX Design

One Visual Language.
Five Purposeful Interfaces.

Operational Legibility

Designed to be readable in one glance. Dispatch cards and map overlays follow a strict visual hierarchy: primary action first, ambient data below the fold.

State-Driven Colour

Orange signals action. Green signals completion. Red signals cancellation. Mappings are applied consistently so users switching roles never relearn the vocabulary.

Touch-First Interaction

All interactive targets meet 44×44pt minimums. The rider app extends this to 56×56pt for critical actions to account for gloves, speed, and stress.

Parallel Journeys, Synchronised

CUSTOMER FLOW

Discover → Order → Track

Primary conversion reaches "order confirmed" in under four taps. Checkout uses a persistent summary drawer; live tracking view becomes the primary screen post-order.

RIDER FLOW

Accept → Navigate → Deliver

Built around a single decision moment. Gets the largest text and fastest response window. Transitions immediately to turn-by-turn navigation once accepted.

VENDOR FLOW

Receive → Confirm → Dispatch

Order queue is the home screen — full-width, chronological, with colour-coded urgency. Confirmations are single-tap, designed for fast counter-speed fulfilment.

05 Technology Base

Systems Powering a Real-Time Ecosystem

Real-Time Dispatch Engine

Matches incoming customer orders to the nearest available rider within seconds using proximity scoring.

Eliminates manual dispatch. Riders receive work continuously, reducing idle time and increasing throughput.

Role-Based Permission Architecture

Each app instance operates under a defined role with strictly scoped API access.

Protects operational integrity. A rider cannot view vendor financials. Ensures UIs are built exclusively around their data scope.

Live GPS Map Layer

Continuous 3–5s position updates. The single feature most correlated with customer trust and reduced support volume.

In-App Payment

End-to-end processing for card, wallet, and COD. Enables real-time earnings settlement to riders (key for retention).

Push Notification Pipeline

Coordinated cross-app alerts timed against operational states, not just DB events. Feels intelligent, not spammy.

Workforce Booking System (Worker App)

Enables businesses to post task-based jobs and engage vetted workers. This vertical diversifies platform revenue beyond logistics while reusing the same assignment, tracking, and payment infrastructure already built for delivery.

One Codebase Strategy, Five Production Apps

The most critical technical decision made early in the project was the choice of React Native for all five apps. The alternative — native Swift and Kotlin development — would have required ten codebases total. React Native's cross-platform model halved the implementation surface while maintaining near-native performance.

  • Frontend: React Native (iOS + Android) & Shared Component Library
  • Backend: Node.js + Express API layer, Firebase Realtime Database
  • Infrastructure: Firebase Auth, Cloud Functions for serverless dispatch
  • Integrations: Google Maps Platform, Payment Gateways, FCM Push
